# 50 只候选池逐桶扩容研究模板

用途：在固定 16 只种子池真实回放可用后，研究下一批跨行业候选。本文是未来工作模板，本次仓库初始化不执行扩容。全局约束见 [AGENTS.md](../../AGENTS.md)，阶段与现状见 [ROADMAP.md](../ROADMAP.md)。

## 使用前填写

```text
本轮目标桶：
信息截止日期与计划开始跟踪日期：
仓库基线提交 / 股票池版本：
现有回放结果与本轮要改善的问题：
候选来源与最多纳入数量：
授权范围：仅研究候选 / 研究并将已批准候选写入配置：
```

读取实际 `universe.csv`、`funds.csv`、`policy.json`、相关输入契约和最新可辨识版本的审计报告，再开展研究。缺少信息时先完成有证据支持的候选分析，不擅自将未批准候选加入正式股票池。

## 可直接交给 AI 的任务

为 `ashare-leader-rotation` 的指定宏观风格桶研究可纳入的 A 股龙头候选。目标是检验新增候选对机会覆盖、集中度、相关性和资金利用的贡献，不以股票数量或历史收益最大化作为完成标准。

遵守以下约束：

1. 保持两份冻结引擎和既定均线、打分、缓冲、预热、费用与执行口径不变；不得针对候选表现寻优。
2. 代码、名称、`bucket`、`subsector` 从配置维护，股票代码保留六位文本，不写代码特例。
3. 采用实际公开信息，记录来源、披露时间、数据所属期和研究取得时间；事实、推断和待核验项分开。
4. 本轮筛选与结果解释适用同一信息截止时点。不要使用截止后财报、行业排名或价格来解释当时的入池决定。
5. 当前种子池为 7 桶：红利、资源、农业、航运、制造、科技成长、医药。未来八桶定义须经确认；从最新 `universe.csv` 核对实际桶名，不自行补造第八桶。`policy.buckets` 的雷达对照桶和 `funds.csv` 的蓝筹 / 成长分组不是股票池全部桶的定义。

### 五项准入研究假设

下列阈值来自项目初始化蓝图，是预先记录的候选筛选假设，尚不构成经过独立验证的收益规律。若数据不足，标为待核验；不能看完回测后静默调整阈值。

| 维度 | 蓝图要求 | 必须提供的依据与限制 |
| --- | --- | --- |
| 财务与行业地位 | 细分行业前 3；排除 ST、高商誉、高质押、持续亏损或纯题材标的 | 明确行业定义、排名指标及出处，使用截止时点已披露的财务和风险资料。“高”和“持续”尚无统一数值定义，先说明拟采用口径及依据，不能凭印象给出通过结论 |
| 流动性与规模 | 常态日均成交额 ≥ ¥3 亿元；市值 ≥ ¥200 亿元 | 在查看候选结果前记录均额窗口、有效交易日分母、市值类型与截止日期；区分正常交易、停牌和上市前空缺 |
| 整手友好度 | ¥450,000 总资金，R2 初始单槽 ¥225,000；优先价格 ≤ ¥112，常规上限 ≤ ¥225；高于 ¥300 的例外需明确说明 | 用当时可得报价、整手、滑点和佣金计算实际可买股数与剩余现金；例外必须有明确纳入理由和资金影响 |
| 选择偏差 | 以有证据的行业地位为理由，不按最近一年涨幅榜挑选 | “长期行业基石”不能消除事后选择现存龙头的偏差。保留候选全集、排除理由与入池决定时间，明确历史验证属于何种研究 |
| 去同质化 | 与现有桶内标的日收益相关性目标 `r < 0.65` | 预先记录观察区间、因果复权收益口径、共同有效日期及样本数；用完整底稿实测，区间短或缺口多时不给出已满足结论 |

整手价格阈值的直观来源是 `100 × 股价 / 225000`：¥112 对应约 4.98%，¥225 对应 10%。这是相对于初始单槽金额的价格粒度估算，未计费用，也不保证净值变化后的实际闲置率。正式诊断应使用每次买入当时的账户净值、槽位、可用现金、费用和成交约束；分别报告整手余量与现金不足。

### 获准写入配置后的验证

先保存扩容前配置和对应结果身份，再将已批准候选追加至 `universe.csv`。新增候选只通过配置与相应上市、交易日线、公司行为底稿进入系统；发现输入协议无法表达的真实事件时报告限制，不绕过校验。

```bash
python fetch_v4_data.py
python run.py --confirm-seeds
python tests/test_engine.py
node tests/ui.cjs
```

上述采集和正式回放应分别检查实际退出状态；采集失败时保留原始数据与缺口，不能以随后生成页面冒充正式通过。`tests/test_engine.py` 已调用 Node parity，正式回放通过数据验收后也会调用真实数据对账；独立排查双端问题时可运行 `node tests/parity.cjs`，无需为每次文档编辑重复整套计算。

对新增配置和完整底稿核验以下结果：

- 本次 `stock_issues == 0`，上市后完整市场日覆盖、真实停牌及权益到账核验通过；同时报告 `etf_issues` 与其影响，ETF 不足不阻断股票轮动。
- Python / JS 全池成交与日净值按分一致，2023-01-20 前缀因果核验通过；工程合成样本不能替代真实回放。
- 在相同信息、日期、费用和执行口径下，对比扩容前后 `W1 / W_Bear / W5 / 2026` 的收益、回撤、收益回撤比、仓位、换手及资金利用；保留旧结果和不利结果。
- 给出 `r >= 0.65` 的冗余对、各对共同样本数、桶与单票集中度，以及新增成员实际改变的信号、成交和账户结果。预测或排名有变化而成交无变化时，先解释决策链。
- 列明基线提交、候选池版本、数据快照、实际命令、退出状态及两份冻结引擎哈希。完整报告入口为 `results/rotation_v4_0_validation.md`，审计入口为 `results/data_audit.json`。

### 结论边界与后续选择

使用当前行业地位和财务状态挑选现存股票，再回放过去，属于带有候选选择偏差的回顾性研究。动态等权基准不会自动消除这种偏差；只有具备历史可得的候选和成员证据，才能提出相应的时点股票池结论。

不得把已反复查看的历史、重叠四窗或同一历史的成本压力情景称为独立未见样本。2026-11-20 之后的数据独立维护，是否构成自然前瞻取决于候选池和规则是否事先记录，以及是否已用于选择。

最终可选择保留种子池、有限新增、暂缓候选或停止本轮扩容。没有贡献或证据不足是可交付的研究结论，不需要继续增加模型、调整参数或扩大股票数量来制造成功。
